## Objective

Implement a per-plan todo-list FSM, exposed through a new `gsd_todo` host-side tool, and integrate it into the executor and verifier workflows.

## Context

- D-04-01: TODOS.md lives next to its PLAN.md.
- D-04-02: Six states: `pending`, `in_progress`, `blocked`, `completed`, `failed`, `skipped`.
- D-04-03: Valid transitions are enforced by the tool.
- D-04-04: `gsd_todo` is the only mutation path.
- D-04-05 to D-04-08: Init, executor updates, verifier checks, atomicity.

## Tasks

### Task 1: Implement `gsd_todo` tool in `extensions/gsd-commands/todo.ts`

**Type:** auto  
**Files:**

- `extensions/gsd-commands/registry.ts`
- `extensions/gsd-commands/backlog.ts` (reference for registry-backed tool)
- `extensions/gsd-commands/index.ts`

**Read first:** Study `registry.ts` artifact loading/saving and how `backlog.ts` parses/rebuilds markdown sections.

**Action:**

1. Create `extensions/gsd-commands/todo.ts` exporting `registerTodoTools(pi)`.
2. Define the `TODOS.md` schema:
   - Frontmatter: `plan`, `phase`, `status`, `created`, `updated`, `completed_tasks`, `total_tasks`.
   - Body sections: `## Pending`, `## In Progress`, `## Blocked`, `## Completed`, `## Failed`, `## Skipped`.
   - Each task entry: `### <taskId>: <title>`, bullet fields (`State`, `Started`, `Completed`, `Reason`, `Depends on`).
3. Implement operations:
   - `init`: read PLAN.md, extract tasks, create TODOS.md with every task in `pending`.
   - `list`: return all tasks (optionally filtered by state).
   - `transition`: validate `from` matches current state, validate target state, move task between sections, append reason if provided.
   - `update`: edit title, reason, or dependencies without changing state.
4. Register `gsd_todo` in `extensions/gsd-commands/index.ts`.

**Verify:**

- `npm run typecheck` passes.
- `npm test` runs the new tests (covered in Task 4).

**Acceptance criteria:**

- `gsd_todo({ operation: "init", planPath: "..." })` writes a valid TODOS.md.
- `gsd_todo({ operation: "transition", taskId: "...", from: "pending", to: "in_progress" })` moves the task.
- Invalid transitions are rejected with `ok: false` and an error message.

### Task 3: Update executor agent to use TODOS.md

**Type:** auto  
**Files:**

- `agents/gsd-executor.md`

**Read first:** Current executor execution flow.

**Action:**

1. Add a step before executing tasks: initialize TODOS.md from the plan (or verify it exists).
2. For each task:
   - Transition task to `in_progress` before acting.
   - On success, transition to `completed`.
   - On blocker, transition to `blocked` and escalate via `contact_supervisor`.
   - On unrecoverable failure, transition to `failed`.
   - On scope decision, transition to `skipped` with a reason.
3. Keep the existing commit protocol and SUMMARY.md output unchanged.

**Verify:** Read the updated agent definition and confirm it references `gsd_todo` for every task state change.

**Acceptance criteria:**

- Executor instructions mention `gsd_todo` at least three times (init, in_progress, completed/failed/skipped).
- Executor no longer suggests writing TODOS.md directly.
