# MISSION.md Format

`MISSION.md` lives at the workspace root. It captures the _reason_ the user is learning this topic.

## Template

```md
# Mission: {Topic}

## Why
{1-3 sentences. The concrete real-world goal. What changes when they have this skill? Avoid "to understand X".}

## Success looks like
- {Specific, observable thing the user will be able to do}
- {Another specific thing}

## Constraints
- {Time, budget, prior commitments, learning preferences}

## Out of scope
- {Adjacent topics explicitly not chased right now}
```

## Rules

- **One mission per workspace.** Two unrelated topics = two workspaces.
- **Concrete over abstract.** "Ship a Rust CLI to my team" beats "learn Rust."
- **Push back on vagueness.** Interview the user before writing a bad mission.
- **Revise when reality shifts.** Update the file; don't leave it stale.
- **Keep it short.** Past one screen, it stops being a compass.
